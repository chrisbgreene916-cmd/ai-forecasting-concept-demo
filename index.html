A conversational agent that generates project-level monthly financial forecasts from Jira story point data. It combines an exported Jira dashboard filter, an MCP-cached hours-per-story-point estimation skill built on historical data, and finance-provided headcount capacity — allocating team hours to projects proportional to remaining incomplete story points.

How the allocation logic works

  • A saved Jira filter is exported from the team dashboard — every open story with points, project, and status
  • An independent estimation skill computes hours-per-story-point from historical Jira completion data — cached via MCP so it's reused across forecasts without recomputing
  • Remaining effort per project = incomplete story points × hours per point
  • Team capacity for the month splits proportionally: if Project A holds 90% of a team's remaining points and Project B holds 10%, then 90% of that team's hours forecast to A
  • Headcount capacity comes from finance, assumed from previous forecast averages unless the user flags a material change

Why this matters

  • Monthly forecasting went from a multi-hour spreadsheet exercise to a single conversational prompt
  • Hour allocations are grounded in actual delivery data rather than gut-feel percentage splits
  • The MCP-cached estimation skill means historical analysis runs once and serves every subsequent forecast
  • Finance receives a consistent monthly spreadsheet — Jan–Apr actuals alongside the May forecast, same format every month
